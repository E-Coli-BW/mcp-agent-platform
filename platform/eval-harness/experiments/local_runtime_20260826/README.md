# Local Runtime Experiment Artifact (2026-08-26)

This directory supports the technical report at
`platform/docs/LOCAL-CODING-AGENT-RUNTIME-TECHNICAL-REPORT-2026-08-26.md`.

## Contents

- `run.py`: experiment runner. It unloads Ollama before every pair,
  retains every generated pair, records model digest/template metadata, and
  validates tool success automatically.
- `results/automated/`: primary all-retained results generated by `run.py`.
  Both requested pairs passed automatic validation and are used in the
  technical report's main table.
- `results/pair-a.json`: accepted cold/warm pair collected after the benchmark
  workspace was corrected during pilot work.
- `results/pair-b-cold-reset.json`: accepted pair collected after an explicit
  `ollama stop qwen2.5:7b` reset.
- `results/provider-cache-contaminated.json`: retained diagnostic pair whose
  nominal cold turn hit Ollama's provider-global cache. It is excluded from the
  primary cold comparison and demonstrates the confound.
- `results/manifest.json`: immutable environment and trial classification.

Raw prompts and answer text were disabled. The JSON contains prompt hashes,
run-local identifiers, call metrics, and prefix hashes, but no JWT or source
contents.

## Reproduction

1. Start Ollama with the exact model digest listed in `results/manifest.json`.
2. Start the agent from the repository root:

```bash
AGENT_AGENT_CONFIG_DIR="$PWD/platform/agent-server/agents" \
AGENT_WORKSPACE="$PWD" \
AGENT_STRICT_TOOLS=false \
AGENT_SKILLS_INDEX_ENABLED=false \
AGENT_KAFKA_BOOTSTRAP_SERVERS='' \
AGENT_RERANK_STRATEGY=none \
AGENT_RUNTIME_STORE_BACKEND=memory \
AUTH_SERVICE_URL=http://127.0.0.1:9 \
AGENT_AUTH_SERVICE_URL=http://127.0.0.1:9 \
platform/agent-server/.venv/bin/uvicorn app.main:app \
  --app-dir platform/agent-server --host 127.0.0.1 --port 8580
```
3. Store the benchmark JWT in a user-private location:

```bash
mkdir -p ~/.local/state/mcp-agent
chmod 700 ~/.local/state/mcp-agent
chmod 600 ~/.local/state/mcp-agent/eval-jwt.txt
```

4. From `platform/eval-harness`, run:

```bash
../agent-server/.venv/bin/python \
  experiments/local_runtime_20260826/run.py \
  --jwt-file ~/.local/state/mcp-agent/eval-jwt.txt \
  --pairs 2 \
  --output-dir experiments/local_runtime_20260826/results/latest
```

The runner uses Ollama's documented `POST /api/generate` with `keep_alive=0`
before each pair. It returns non-zero if a turn fails, the cold turn does not
successfully read `README.md`, the warm turn rereads the file, a tool reports an
error, or the system-prefix hash changes.

## Selection Disclosure

This was an exploratory engineering experiment, not a preregistered study. Two
pilot runs made before setting `AGENT_WORKSPACE` correctly are not part of the
final protocol because the tool could not access the target file. After the
workspace correction, three pilot pairs are archived here. The
provider-cache-contaminated run is retained and excluded from the cold analysis
because its first-call load/prefill values show that it was not cold. The future
runner removes this discretionary step by unloading the model before every
pair and retaining every result. The primary `results/automated/` run was then
generated with that runner: exactly two pairs were requested, retained, and
accepted automatically.
