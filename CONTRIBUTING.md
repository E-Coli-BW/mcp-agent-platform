# Contributing

Thanks for helping improve MCP Agent Platform.

## Before opening a pull request

1. Open an issue for a non-trivial feature or architectural change.
2. Keep the pull request focused on one problem.
3. Add or update tests for behavior changes.
4. Run the documented checks locally.
5. Explain compatibility, security, and performance trade-offs in the PR.

## Code and comments

Prefer clear names and small functions. Add comments for invariants, security
boundaries, compatibility constraints, and non-obvious trade-offs. Do not add
personal paths, internal URLs, credentials, private prompts, or unreproducible
benchmark claims.

## Pull requests

Use a concise title, describe the user-visible effect, list the tests run, and
call out any known limitations. Unrelated formatting and generated artifacts
make review harder and should be avoided.
